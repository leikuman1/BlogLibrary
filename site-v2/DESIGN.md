# Blog v2 Design Standard

目标：把 Blog v2 做成一个简洁、克制、结构严密的技术知识库。视觉方向参考 `pi.dev`：少装饰、强信息层级、终端/工程感、黑白中性色、代码块清晰、内容优先。最终观感应像“一个有严重代码洁癖的顶级架构师维护的博客站”。

> 参考对象：`https://pi.dev/` 当前呈现为极简技术产品页：顶部导航简洁，支持 Auto/Light/Dark 主题，页面大量使用命令、代码、终端式文本、短标题和高密度信息块。

## 1. 设计原则

### 1.1 内容优先

- 页面第一目标是阅读和检索，不是展示装饰。
- 首页必须直接呈现书籍、标签、搜索和最近内容，不做营销式大 Hero。
- 每个视觉元素都要回答一个问题：它是否帮助用户更快找到、判断、阅读内容。

### 1.2 严格秩序

- 所有页面使用统一栅格、统一间距、统一边框、统一字号层级。
- 组件不能为了“好看”随意变形；同类内容必须有同类尺寸和布局。
- 所有卡片、按钮、输入框、代码块、目录项都按 4px/8px 节奏对齐。

### 1.3 工程感

- 视觉语言接近代码编辑器、终端、文档站，而不是插画博客或个人主页。
- 元信息要清晰：书籍状态、章节数量、更新时间、标签、所属部分。
- 能用文本、边框、代码块表达的地方，不使用多余图片。

### 1.4 克制但不冷淡

- 颜色少，但要精确。
- 动效少，但要有响应。
- 页面干净，但不能像默认模板。

## 2. 视觉基调

### 2.1 关键词

- Minimal
- Sharp
- Dense
- Technical
- Quiet
- Precise
- Architecture-grade

### 2.2 禁止方向

- 不做大面积渐变背景。
- 不使用玻璃拟态、彩色光斑、漂浮装饰球。
- 不使用过度圆角；卡片和按钮最大 8px。
- 不做大幅营销 Hero。
- 不使用花哨动效、弹跳动效、旋转动效。
- 不使用卡片套卡片。
- 不让页面看起来像 Notion 模板、AI SaaS 官网或二次元主页。

## 3. 色彩系统

色彩必须服务于结构。默认以浅色为主，后续可加深色模式。

### 3.1 基础色

```css
:root {
  --bg: #fafafa;
  --surface: #ffffff;
  --surface-subtle: #f4f4f5;
  --text: #111111;
  --text-muted: #5f6368;
  --border: #e4e4e7;
  --border-strong: #c7c7cc;
}
```

### 3.2 强调色

强调色只用于当前状态、链接、选中标签、焦点边框。

```css
:root {
  --accent: #0f766e;
  --accent-soft: #ccfbf1;
  --danger: #b91c1c;
  --warning: #a16207;
  --info: #1d4ed8;
}
```

### 3.3 使用规则

- 页面背景只用 `--bg`。
- 卡片、内容区、导航用 `--surface`。
- 边界只用 1px border，不用重阴影。
- 阴影仅用于浮层和管理员入口，且极轻。
- 每屏主色数量不超过 3 个。

## 4. 字体与排版

### 4.1 字体栈

```css
font-family:
  Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "Microsoft YaHei", sans-serif;

font-family-mono:
  "JetBrains Mono", "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

### 4.2 字号

```css
--text-xs: 12px;
--text-sm: 14px;
--text-md: 16px;
--text-lg: 18px;
--text-xl: 24px;
--text-2xl: 32px;
--text-3xl: 44px;
```

### 4.3 排版规则

- 正文使用 16px，行高 1.75。
- 章节页正文最大宽度 760px。
- H1 只在页面标题使用，不能到处放大。
- H2/H3 要像技术文档标题，不做花哨装饰。
- 元信息、标签、路径、更新时间使用 12px 或 13px。
- 代码、路径、命令、版本号全部使用 monospace。
- 不使用负 letter-spacing。

## 5. 布局系统

### 5.1 页面宽度

```css
--container: 1120px;
--article: 760px;
--sidebar: 260px;
```

### 5.2 间距

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-6: 24px;
--space-8: 32px;
--space-12: 48px;
```

### 5.3 栅格

- 首页：左侧主内容，右侧可选索引/最近更新；移动端单列。
- 书籍页：左侧书籍目录，右侧章节列表。
- 章节页：正文居中，右侧 TOC；窄屏 TOC 下沉到正文前。
- 所有列表项高度可预期，不因 hover、标签数量、按钮状态导致布局跳动。

## 6. 组件标准

### 6.1 顶部导航

目标：像工具，不像菜单装饰。

- 高度：56px 或 64px。
- 背景：纯色或轻微透明，不使用强毛玻璃。
- 左侧：站点名 `L's Library`。
- 右侧：`Books`、`Tags`、`Search`、`About`。
- 主题切换文本可采用 `Auto Light Dark` 形式，参考 `pi.dev`。

### 6.2 首页书籍列表

首页不要做传统博客文章流。书籍展示应更像“技术索引”。

每本书必须包含：

- 书名
- 一句话定位
- 标签
- 章节数
- 最近更新时间
- 状态：`active` / `planned`

推荐视觉：

- 卡片边框 1px。
- 无重阴影。
- 左侧可有窄书脊色条，但不做复杂封面。
- hover 只改变边框、背景或轻微位移。

### 6.3 标签筛选

- 标签是过滤器，不是装饰。
- 选中态只用背景色和边框变化。
- 标签数量多时允许横向滚动或换行。
- 标签文案应短，不超过 8 个中文字符为佳。

### 6.4 搜索

搜索框要像命令输入：

- 高度 40px 或 44px。
- 左侧搜索图标。
- 输入框边框 1px。
- 聚焦态使用 `--accent` 边框。
- 搜索结果按“书籍 / 章节”区分。

### 6.5 书籍页

书籍页是目录，不是详情广告页。

必须展示：

- 书名
- 简介
- 标签
- 目录分组
- 每组章节
- 最近更新时间

目录项必须清楚显示章节标题和摘要。

### 6.6 章节页

章节页以阅读体验为核心。

必须展示：

- 面包屑
- 所属书籍
- 所属章节组
- 正文
- 本页 TOC
- 上一篇 / 下一篇

正文样式：

- 代码块背景深色，边框 1px。
- 行内代码使用浅底色。
- 图片最大宽度 100%，边框 1px，圆角 8px。
- 表格必须可横向滚动。

### 6.7 管理员角色

管理员角色是后续 Agent 入口，占位即可。

- 右下角固定。
- 默认收敛为小按钮或小头像。
- 不遮挡正文和导航。
- 未开放状态必须明确。
- 不使用夸张气泡和大面积插图。

## 7. 图片策略

图片由用户手动生成，不在工程里接入生图 API。

### 7.1 允许的图片

- 书籍封面
- 管理员头像
- 图书馆背景细节
- 章节内说明图

### 7.2 图片风格

- 简洁、低饱和、技术文档感。
- 不要动漫大头贴式封面。
- 不要复杂背景。
- 不要强烈赛博霓虹。
- 图片应像技术书或工具文档资产，而不是社交媒体插画。

### 7.3 推荐路径

```text
public/images/generated/books/
public/images/generated/admin/
public/images/generated/library/
public/images/content/
```

### 7.4 缺图处理

- 缺封面时使用 CSS 书脊占位。
- 缺管理员头像时使用文字或极简符号占位。
- 不允许出现 broken image。

## 8. 文案风格

文案要像架构师写给工程师看的索引。

### 8.1 原则

- 短句。
- 信息密度高。
- 不卖弄。
- 不用空泛形容词。
- 不写“欢迎来到我的博客”。
- 不解释显而易见的 UI。

### 8.2 示例

推荐：

```text
把知识点收进书架。
32 篇笔记，12 本书，按主题维护。
Git：版本控制与团队协作。
```

避免：

```text
欢迎来到我的知识世界，让我们一起探索技术的海洋。
这里有丰富多彩的内容等待你的发现。
```

## 9. 动效与交互

### 9.1 允许

- hover 边框变化。
- focus ring。
- 120ms 到 180ms 的透明度或背景色过渡。
- 搜索结果即时过滤。

### 9.2 禁止

- 大幅位移。
- 弹跳动画。
- 自动滚动。
- 粒子背景。
- 光斑漂移。
- 打字机动画。

## 10. 深色模式

后续可以加入 `Auto Light Dark`，但第一版先保证浅色模式。

深色模式要求：

- 背景接近 `#0f1115`。
- 卡片接近 `#151821`。
- 文本接近 `#f4f4f5`。
- 边框不能消失。
- 代码块和页面背景要有明确层级。

## 11. 实现落地要求

后续改 UI 时必须遵守：

- 全局 token 写在 `src/styles/global.css`。
- 组件不写一次性色值，除非是局部语义色。
- React 组件只负责交互，不塞大量视觉决策。
- Astro 页面负责布局和数据组织。
- 书籍和章节样式必须复用统一 class。
- 每次 UI 改动后运行 `npm run build`。

## 12. 当前站点需要调整的方向

现有第一版图书馆 UI 已经能跑，但风格偏温暖图书馆。后续应收敛为：

- 更少渐变。
- 更少阴影。
- 更清晰边框。
- 更强文档站密度。
- 更像技术工具首页。
- 书籍卡片从“封面感”转向“索引卡/书脊信息块”。
- 管理员组件从“气泡角色”转向“克制入口”。

## 13. 验收标准

完成视觉重构后应满足：

- 首页不显得花哨。
- 10 秒内能看懂站点结构。
- 标签和搜索比装饰更突出。
- 章节页阅读无干扰。
- 页面像技术专家维护的知识库，而不是模板博客。
- 所有 UI 在移动端不重叠、不溢出。
- `npm run build` 通过。
